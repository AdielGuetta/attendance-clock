# תרגול לפני ההצגה: שני שינויים

שני תרגילים קצרים. הראשון ידני, כדי להרגיש איך שינוי עובר מהקוד למסך. השני עם Claude Code, כדי לתרגל עבודה לפי `CLAUDE.md` ותוכנית.
עובדים על ענף נפרד, כדי שהגרסה להגשה ב-`main` לא תשתנה:

```bash
git switch -c practice
```

בסוף חוזרים עם `git switch main`, ואם רוצים, מוחקים את הענף: `git branch -D practice`.

---

## תרגיל 1: שינוי ידני (כ-5 דקות): עובד רביעי

**המטרה:** לראות איך שורה אחת בסקריפט המסד מגיעה עד לרשימת העובדים במסך.

1. פותחים את `backend/Attendance.Api/Database/schema.sql`. בסוף הקובץ יש שלוש שורות שמוסיפות עובדים לדוגמה.
2. מעתיקים את השורה האחרונה ומשנים בה את המספר ל-4 ואת השם, למשל:
   ```sql
   IF NOT EXISTS (SELECT 1 FROM dbo.Employees WHERE Id = 4) INSERT INTO dbo.Employees (Id, FullName) VALUES (4, N'דנה אברהם');
   ```
   ה-`N` לפני השם נדרש כדי שעברית תישמר נכון.
3. בונים ומריצים מחדש:
   ```bash
   docker compose up --build -d --wait
   ```
4. מרעננים את http://localhost:8080. העובדת החדשה מופיעה ברשימה, ובדוח המנהל עם 0 שעות.
5. שומרים את השינוי:
   ```bash
   git commit -am "Add a fourth sample employee"
   ```

**מה להסביר בהצגה:** הסקריפט "אידמפוטנטי". הוא רץ בכל עלייה של השרת ומוסיף רק מה שחסר, ולכן הנתונים הקיימים לא נמחקים.
**אם משהו לא עבד:** `docker compose logs app` מראה את השגיאה. הסיבה הנפוצה היא גרש חסר או פסיק בשורת ה-SQL.

---

## תרגיל 2: שינוי עם Claude Code (כ-15 דקות): סימון "יציאה שנשכחה" בדוח

**המטרה:** שינוי שנוגע בשרת, בממשק ובבדיקות, ותרגול של בדיקת העבודה של Claude Code.

1. פותחים את Claude Code בתיקיית המאגר. הוא קורא את `CLAUDE.md` לבד.
2. מבקשים, למשל:

   > בדוח המנהל, סמן משמרת שפתוחה יותר מ-12 שעות בתור "ייתכן ששכחו להחתים יציאה".
   > החישוב בשרת, ב-`ReportBuilder`, לפי שעון השרת (זו תצוגה ולא שעת החתמה). הוסף שדה לתשובה, הצג אותו ב-`ManagerReport.tsx`,
   > והוסף בדיקת יחידה ב-`ReportBuilderTests`. תתחיל מתוכנית קצרה ב-`.claude/plans/`, ובסוף עדכן את `docs/TESTING.md`.

3. **מה לבדוק בתשובה של Claude Code:**
   - שהוא כתב תוכנית לפני הקוד.
   - שהוא לא השתמש בשעון השרת כדי לקבוע שעת החתמה. מותר רק לתצוגה, לפי הכלל הראשון ב-`CLAUDE.md`.
   - שנוספה בדיקה, ושהשינוי נוגע רק בקבצים הצפויים: `ReportBuilder.cs`, `Models.cs` אם צריך, `api.ts`, `ManagerReport.tsx` והבדיקות.
4. בודקים בעצמכם:
   ```bash
   docker compose up --build -d --wait
   ```
   החתימו כניסה לעובד, ואז בקשו מ-Claude Code להראות איך לבדוק את הסימון בלי לחכות 12 שעות (למשל דרך הבדיקה עם שעון מזויף).
5. דוחפים את הענף (`git push -u origin practice`) ומסתכלים בלשונית Actions שהבדיקות עברו. **לא ממזגים ל-`main`.**

**מה להסביר בהצגה:** איך `CLAUDE.md` מכוון את Claude Code (כללים, פקודות, איפה לתעד), ושההחלטה הסופית והבדיקה הן שלכם.

## תרגיל בונוס (2 דקות): הדגמת נפילה של שירות הזמן

```bash
docker compose -f compose.yaml -f compose.outage.yaml up -d --wait app
```

לוחצים "החתמת כניסה". אחרי כמה שניות מופיעה ההודעה ששירות השעה אינו זמין, והכפתור מתחלף ל-"נסו שוב". שום דבר לא נשמר.
מחזירים למצב רגיל ולוחצים שוב "נסו שוב". ההחתמה נשמרת עם אותו מספר זיהוי:

```bash
docker compose up -d --wait app
```
